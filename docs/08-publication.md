# 08 — Public showcase boundary

This repository is a curated research specification with synthetic examples and documentation checks. Detailed internal delivery plans are excluded. The detector is not implemented or evaluated; publication of a specification alone does not demonstrate an algorithm's performance.

## Appropriate public evidence after implementation

A concise README with honest status, a small original synthetic demo, representative generic method code, reproducible public benchmark methodology, a model card, real test outputs and an explanation of limitations can demonstrate engineering ability. Publish enough code and data for the specific claimed public result to be reproduced. If a private method cannot be released, describe its evaluation and limits honestly instead of claiming a fully reproducible open implementation.

Keep customer records, private agreements, bank/provider integrations, private investigation notes, real alert thresholds, private commercial plans and untouched held-out labels outside the public export. Do not claim that public code cannot be copied. Private repositories restrict ordinary access but do not establish a legal monopoly or make leaks impossible. Language choice is not a protection mechanism.

## Release procedure

1. Inventory each change deliberately. Include only reviewed research documentation, original public fixtures and implemented code or measured results whose status is explicit. Internal delivery plans and private records remain outside the public repository.
2. Review every staged diff, generated image, HTML asset, notebook output, metadata field and commit identity. Verify no credentials, real financial records, personal affiliations or private absolute paths are included.
3. Verify data and dependency licensing, preserve required attribution and choose the project's license explicitly. A public repository is not itself a selected open-source license.
4. Reproduce the result using only the selected export. If omitted private content is required, change the claim or publish a different reproducible demonstration.
5. Use the owner's configured author identity and clear commit messages. Avoid automated coauthor trailers and promotional tooling signatures. Do not alter third-party credit or invent individual contributions.
6. Review the public page for false completion, award, certification, institution affiliation or novelty claims. A rigorous project may support applications or research submissions; recognition is decided independently by external bodies.
7. Record the exported file hashes, checks and license decision. Upload only within the maintainer's authorized publication scope.

The project's learning value comes from correct methods, measured findings, thoughtful tradeoffs and reproducibility. Attractive diagrams support that evidence; they cannot replace it.
