# 05 — Definition of done

## Documentation ready — current category

The source documents, requirements and acceptance-test registers, schemas and synthetic example specifications are internally consistent, and the documentation validator records checks. This does not imply an application exists. The validator must never mark application tests complete.

## R1 engineering complete — future gate

All mandatory requirements have implemented behavior and linked passing acceptance evidence. The simulator, eligible-history engine, split generator, four baseline families, two feature ablations, calibration, bounded queue, metric suite and escaped report work from a clean environment. Tests cover malformed input, scope isolation, future observations, delayed labels at every supervised stage, pre-test artifact freezes, stage coverage failures, resolved-only metric denominators, both selected and unselected unknown outcome bounds, per-bootstrap queue recomputation, missing context, duplicate conflicts, unsupported currency mixing and unsafe report content. There is no external financial action. The run manifest is complete and every case outcome, including error and unknown, is visible.

A colleague can follow documented setup, reproduce deterministic fixtures and regenerate the statistical tables without hidden files beyond explicitly reviewer-held labels. Model artifacts have provenance. Runtime and memory are measured on named hardware. Application statuses move to complete only after evidence links are recorded.

## Research complete — future gate

A frozen protocol, all specified baselines and ablations, five predetermined seeds, held-out temporal and cold-component tracks, mature-label coverage, uncertainty estimates and failure analysis are present. The result card records limitations and any protocol deviations. Raw synthetic outputs and computation steps are retained so metrics can be checked. A negative hypothesis result still satisfies research completion if the experiment is sound.

## Evaluated public showcase ready — separate future gate

The current public edition is a research specification. An evaluated showcase will show implemented capabilities, a small runnable synthetic demo, actual measured results, test evidence, design reasoning and acknowledged limitations. It omits production controls, customer records, private evaluation seeds before final scoring, private commercial plans and unreviewed claims. License and third-party notices are decided explicitly. A snapshot alone is not an award, accreditation or evidence of external adoption.

## Production ready — not in this scope

A bank or payment provider would require institution-specific labels, data rights, independent validation, governance, privacy/security assessment, monitoring, operational controls and appropriate review before considering a pilot. This blueprint neither specifies nor completes that readiness process. R1 remains an educational and research artifact.
